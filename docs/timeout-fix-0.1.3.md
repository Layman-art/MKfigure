# MK Figure 0.1.3：Codex 复刻超时修复

## 原因与证据

0.1.2 对所有非生图 Codex 请求使用固定 300 秒总期限，从启动连接起计算；即使模型仍有推理或文本事件，到期也会中断并销毁该请求的进程。报错与用户截图中的“请求超时（300 秒）”一致。

实际项目使用 Codex、高推理强度，模型配置为空。现有自动选择逻辑会读取模型列表第一项，但界面显示“待设置”，造成状态不一致。模型活动回调没有绑定到工作流，因此 UI 只能显示静态阶段。

新增本地虚拟时间 / 假 stdio 回归首先复现了“持续活动到第 6 分钟前仍被 300 秒期限杀死”，不是通过缩短真实请求来猜测问题。

## 修复

- Codex 请求持续收到所属任务的模型活动时，续期无活动计时；连续 10 分钟无响应时终止，整次单个请求另设 30 分钟上限。连接握手和 RPC 启动仍保留短超时。
- 不把 UI 自己的计时刷新当成模型活动。其他 thread / turn 的事件不能续期或结束当前请求。
- 显示实际模型、阶段与已用时间；原始推理文本不显示、不记录到进度。回调按请求绑定项目，不串项目，不在取消后继续更新。
- stdout 提前关闭时及时报告连接结束；用户取消、启动失败、成功和超时均清理请求计时器。
- 失败写入项目历史，原图保留；不自动重试收费请求。自动选模时显示“自动选择”，没有变更用户的模型选择行为。
- 首次真实大图测试越过 300 秒并持续收到输出，720 秒后返回，但暴露了 provider 提前拒绝无效 JSON、使工作流修复不可达的问题。已让 Codex 返回文本先保存，再由工作流解析、校验并最多修复一次；修复失败时两份文本也保留。要求紧凑 JSON，仅减少空白，不删图形内容。
- 本次针对 Codex 流式流程。兼容 API 的非流式请求超时策略没有扩大修改。

协议依据：[Codex App Server 生命周期](https://learn.chatgpt.com/docs/app-server#lifecycle-overview)。`turn/start` 后继续接收通知，最终以 `turn/completed` 判定完成。

- 51 项单元测试通过，2 项默认在线测试跳过。
- 新增 13 项超时与生命周期回归，包括持续活动超过五分钟、十分钟无响应、三十分钟上限、跨任务事件、提前断流、预取消、启动失败和进度观察者异常。
- 另有 2 项真实 Workflow + Store + CodexProvider / 模拟 stdio 集成测试，验证先保存无效响应、一次修复成功落盘，以及修复失败保留原图和诊断文本。
- TypeScript 和 unused 声明检查通过。
- Windows 打包程序的离线启动、参考图导入和 PPTX/SVG/PNG 导出 smoke 通过。
- 已将本机 `D:\MKfigure\MK Figure` 升级到 0.1.3，安装器退出码 0，安装后的 ASAR 与最终构建一致。升级前后项目、图片及连接设置共 5 个文件 SHA256 不变。安装目录中的程序再次通过离线 smoke 和 14 个界面状态检查。
- 实际大图验证使用用户项目的独立副本，沿用高推理强度，由自动选择得到 `gpt-6-astra`；没有重新生图。
