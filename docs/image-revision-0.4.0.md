# 0.4.0 视觉稿修改与低推理验证

## 本次变化

- 视觉稿页面增加“直接提示词”和“按改进意见”两种方式。直接提示词由用户选择是否附当前图片；不带图时仅使用新提示词重新生成。
- 按意见修改先用同一模型和推理档位整理修改指令，再把原图与指令送给原生图像工具。与直接改图相比，多一次文本模型调用。
- 三种操作均不自动附加旧风格参考。成功后保留原图和新版本，取消或失败保留原来的目标图和输入意见。
- 选择另一个视觉稿版本时立即清除旧可编辑预览和检查结果；需要针对新的目标图重新复刻。用量摘要显示最近一次改图的耗时与 token。
- 全局 `mk-figure-skill` 与软件附带副本同步精简：四文档从 10,535 缩至 6,027 字符，减少 42.8%。删除无用的 `ppt-editable` 说明、重复通用要求和固定工具优先级，保留字体、科学内容和可编辑验证约束。原文备份在 `output/skill-backup-2026-09-19`。

## 可追踪的输入

`generation/operation-<runId>.json` 记录动作、模型、推理档位、用户意见、实际发送的提示词、来源图片与结果图片标识。它保存在作品内部，不混入 PPTX/SVG 导出目录，也不包含登录凭据或图片 Base64。

当前采用临时 Codex 会话，因此不会同步为 Codex 桌面里的普通聊天。软件实际发送的提示词由源码组合，`resources/skill` 是随包参考文档，不是运行时执行入口。详见 [数据流与代码入口](data-flow.md)。

## 验证

- 130 项离线测试通过，2 项在线测试默认跳过；新增动作覆盖原样提示词、旧参考隔离、低档位传递、用量累加及取消/失败保留原图。
- `scripts/image-revision-ui-smoke.mjs` 在隔离 Electron 环境中核对三种选择对应的真实 IPC 参数、失败后输入保留、旧场景立即失效及 1440/960 窗口布局。该脚本替换模型请求，不将它算作在线效果验证。
- 独立在线测试采用当前账户实际支持的 `gpt-6-astra/low`，限次执行首次生成、直接改图、按意见改图、无图重画和可编辑复刻。账户是 Pro，因此不是 Plus 账户或 Plus 配额测试。
- 在线请求、返回图、时间、服务器 token 及导出结果保存在 `output/low-reasoning-2026-09-19`。具体质量结论以该目录的验收报告为准；不根据结构检查或对象数量判断图片保真。

在线五动作已完成，共六次模型请求，约 6 分 32 秒、169,830 个回传 token（含缓存输入）。两条原图修改路线均按要求改色；新生图未遵从 2:1，实际为 3:1；可编辑复刻的 ODE 求解器公式局部重叠，渐变转为纯色。原始结果保留，未用额外高推理调用或人工修图替换测试结果。

PowerPoint 16.0 原生核验了 62 个文本，未出现导出新增换行；在副本中改标题、改公式组件、移动形状，保存重开均成功。公式重叠在工作台和 PowerPoint 中都存在，不能判为可直接交稿。详细记录见 [低推理验收](../output/low-reasoning-2026-09-19/review.md)。

最终 Windows 打包版另通过三种改图入口的界面回归，测试对模型调用使用替身；真实效果证据来自上述独立低推理测试。安装包为 `release/MK-Figure-0.4.0-Windows-x64-Setup.exe`，原有安装目录和真实应用配置未被修改。

`low` 控制 GPT 任务的推理强度，不证明内部图像工具也采用同一档位或某个固定图像模型。少量样本不能代表所有复杂科研图；token 不等于 Plus 可用额度。
